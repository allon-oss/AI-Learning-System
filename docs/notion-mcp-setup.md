# Notion MCP 配置与使用边界

## 文档目的

本文记录 Personal Learning System 项目接入 Notion MCP 的长期配置知识、使用边界与安全原则，供后续维护和扩展参考。

Personal Learning System 仍然是项目核心：系统以学习主题、学习资料、今日计划、学习笔记和学习进度为 V1 基础记录流程。Notion MCP 是 AI 能力扩展模块，用于让 AI 在获得授权时读取或协助处理 Notion 内容；它不替代本项目的数据管理方案，也不改变既有 V1 模块规划和“学习记录回看 V1.1”的后续方向。

## MCP 是什么

MCP（Model Context Protocol，模型上下文协议）是一种让 AI 客户端以统一方式连接外部工具和数据源的协议。通过 MCP，Codex 可以发现并调用经过配置的 Notion 工具，而不是依赖手动复制粘贴内容。

在本项目中，MCP 的作用是提供一个受控的 Notion 访问通道。它属于 AI 辅助能力，而非 Personal Learning System 的主数据层。

## 为什么接入 Notion MCP

Notion MCP 可在明确授权的范围内帮助 AI：

- 读取与学习、项目或知识管理相关的 Notion 页面；
- 检索已授权的资料，辅助整理、总结或建立关联；
- 在未来经人工确认后，协助把学习成果同步到指定的 Notion 页面或数据库。

本地 Personal Learning System 保持其自身的数据与功能边界。即使 Notion MCP 暂时不可用，现有 V1 学习记录流程也应继续可用。

## 当前配置流程

当前采用本地 MCP 服务配置，服务名为 `notion_readonly`。

1. 在 Notion 创建集成，并为集成授予完成目标所需的最小能力。
2. 仅将需要访问的指定 Notion 页面或数据库共享给该集成；未共享的内容不应被访问。
3. 将集成 Token 保存在本机受保护的配置或凭据位置，由本地启动脚本读取。Token 不写入项目源码、文档、Git 提交或命令历史。
4. 在 Codex 本机配置中注册 `mcp_servers.notion_readonly`，指定本地启动脚本，并启用服务。
5. 将工具默认审批模式设为 `prompt`，使可能改变 Notion 内容的调用需要明确确认。
6. 重启或刷新 Codex 会话后，用只读身份接口验证服务是否能启动、Token 是否有效、工作区是否可访问。

配置文件和启动脚本都属于本机运行环境，不属于项目仓库；项目仓库只保存长期维护说明，不保存密钥、绝对本机路径或临时执行输出。

## 权限设计

### 基本原则

- 最小权限：只授予完成当前任务所必需的 Notion 权限。
- 最小范围：只共享指定页面和数据库，不将整个工作区默认暴露给集成。
- 先读后写：日常检索、总结和同步前检查优先使用只读操作。
- 写入需确认：创建、更新、移动、归档或删除 Notion 内容前，必须先说明目标、影响范围和拟写入内容，并取得明确确认。
- 可追溯：涉及写入时，记录操作目的、目标页面或数据库及结果；不记录 Token。

### 当前边界

当前服务使用 `notion_readonly` 名称，并配置为提示审批模式。该名称表达默认使用策略，但不能单独作为安全边界：工具清单可能包含 Notion API 的修改类接口。因此，是否允许写入应由 Notion 集成能力、页面共享范围和每次操作的显式审批共同控制。

## Token 安全管理

- Token 仅保留在本机受保护的配置、凭据存储或启动环境中；不得放入仓库文件。
- 不在 Markdown 文档、截图、聊天记录、终端输出或 Git 提交信息中展示 Token。
- 将 Token 所在的配置文件和启动脚本排除在版本控制之外，并在提交前检查 `git diff` 和 `git status`。
- 怀疑泄露、人员变动或不再使用时，立即在 Notion 端撤销旧 Token，并创建和替换新 Token。
- 定期检查集成的权限能力与已共享页面，移除不再需要的访问范围。

## 当前测试结果

已完成的验证：

- 本机 Codex 配置中已注册并启用 `notion_readonly` MCP 服务。
- Codex 会话能够发现该服务提供的 Notion 工具。
- 已成功调用只读身份接口并获得已授权 Notion 工作区中的集成机器人身份，确认本地启动、认证和工作区连通性正常。
- 本次验证没有读取业务页面、查询数据库或写入、移动、归档、删除任何 Notion 内容。

尚待按实际使用场景验证：

- 指定页面的读取权限是否符合预期；
- 指定数据库的检索范围与结果质量；
- 经明确审批后的最小化写入流程，以及失败、限流和权限不足时的提示方式。

## 后续扩展方向

1. 为学习复盘建立受控的 Notion 检索入口：只检索明确授权的学习页面或数据库。
2. 在 Personal Learning System 的“学习记录回看 V1.1”稳定后，探索将已确认的学习总结导出到指定 Notion 页面；本地系统仍保留主流程和数据边界。
3. 为未来 AI 能力增加操作分级：默认只读、草稿预览、人工确认后写入。
4. 建立错误处理规范，覆盖未授权页面、Token 失效、网络异常、速率限制和写入冲突。
5. 在有明确需求后再评估双向同步；在此之前，不把 Notion 作为替代或唯一的数据管理来源。
