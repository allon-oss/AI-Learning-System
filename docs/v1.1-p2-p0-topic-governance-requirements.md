# V1.1 P2 P0：主题编辑、归档与删除影响处理

**状态：已确认，尚未开发**
**确认日期：2026-08-24**

## 1. 用户场景

1. 用户误创建主题，或主题名称、学习状态、所属父主题需要调整。
2. 用户暂时不再学习某个主题，希望从日常列表隐藏，但不能丢失既有学习历史。
3. 用户归档一个父主题时，希望其全部子主题一并停止使用，避免主题树出现断裂。
4. 用户需要查看归档主题关联过的资料、计划、笔记和进度，并继续编辑这些历史内容。
5. 用户归档前需要明确知道影响范围，避免误以为数据会被删除。
6. 用户希望在需要时恢复整组归档主题，继续正常学习。

## 2. 功能范围

### 2.1 主题编辑

- 支持编辑主题名称、学习状态和父主题。
- 学习方向不可编辑。
- 调整父主题时，禁止将主题移动到自身或其任意子主题下。
- 调整父主题不修改主题 ID，也不修改已有资料、计划、笔记和进度的关联。
- 已归档主题必须先恢复，才能编辑。

### 2.2 主题归档

- 支持归档任意主题。
- 归档父主题时，父主题及全部子主题一并归档。
- 归档前显示确认提示，包括：
  - 将归档的主题数量；
  - 关联资料、计划、笔记、进度记录的数量；
  - 历史数据仍会保留；
  - 归档后不可新增或改关联到这些主题；
  - 本阶段不会删除任何数据。
- 正常主题列表和新建表单不显示已归档主题。
- 已归档主题不可用于：
  - 新建资料；
  - 新建计划；
  - 新建笔记；
  - 新建进度记录；
  - 将既有记录改关联到该主题；
  - 作为其他主题的新父主题。

### 2.3 历史数据与归档状态

- 不修改已有资料、计划、笔记、进度中的 `topicId`。
- 已有关联内容可继续编辑自身内容。
- 历史记录保留原主题名称，并明确显示“主题已归档”。
- 编辑历史记录时，原归档主题关联只读保留；主题选择项不显示已归档主题。

### 2.4 查看与恢复

- 提供“已归档主题”入口。
- 已归档主题列表和详情页明确显示“已归档”状态。
- 只允许从一组归档主题的最上层父主题恢复。
- 恢复父主题时，父主题及全部被级联归档的子主题一并恢复。
- 子主题不单独提供恢复操作，避免出现父主题仍归档、子主题已恢复的结构错误。

## 3. 不包含内容

- 不实现主题的直接删除或永久删除。
- 不实现批量归档、批量恢复。
- 不允许修改学习方向，或自定义新的学习方向。
- 不调整资料、计划、笔记、进度记录自身现有的删除规则。
- 不做回收站、定时自动归档、备份恢复、导入导出。
- 不做筛选、统计图表、提醒、AI 建议等后续能力。

## 4. 数据影响

- 主题数据增加独立的归档状态；归档不等同于主题原有的学习状态。
- 为支持兼容已有本地数据，缺少归档字段的旧主题默认视为“未归档”。
- 建议保存以下归档信息：
  - `isArchived`：是否归档；
  - `archivedAt`：归档时间；
  - `archiveRootId`：本次级联归档的顶层主题 ID，用于限制只能从顶层主题恢复。
- 归档和恢复只更新主题数据，不删除或改写资料、计划、笔记、进度的历史关联。
- 编辑父主题时保持主题 ID 不变；关联记录无需迁移。
- 若主题改变父级，应重新放入新父级的同级排序范围，且不破坏其他主题已有排序。

## 5. 测试方案

### 5.1 自动测试

- 旧主题数据没有归档字段时，可正常加载为未归档状态。
- 编辑名称、学习状态、父主题后，刷新页面仍保留修改。
- 禁止修改学习方向。
- 禁止将主题移动到自身或任意子主题下。
- 归档父主题时，所有子孙主题均被归档。
- 归档不修改资料、计划、笔记、进度记录的 ID、内容和 `topicId`。
- 归档后，已归档主题不会出现在新建和改关联的主题选择项中。
- 恢复顶层归档主题时，整棵被归档子树恢复。
- 子主题无法单独恢复。
- 不提供主题直接删除的数据操作或界面入口。

### 5.2 页面回归测试

- 归档确认提示正确展示主题及四类关联数据的数量。
- 取消归档后，页面和本地数据均不变化。
- 正常主题列表不显示归档主题；“已归档主题”入口可查看完整归档树。
- 资料、计划、笔记、进度的历史区域能显示“主题已归档”。
- 已有关联内容可以编辑，但不能重新选择已归档主题。
- 已归档主题不可编辑；恢复后可再次编辑和关联。
- 归档、恢复、编辑后，键盘焦点、选中状态和移动端布局正常，390px 宽度无横向溢出。
