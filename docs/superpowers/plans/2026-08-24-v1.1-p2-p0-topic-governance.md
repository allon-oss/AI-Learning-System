# V1.1 P2 P0 主题治理 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 支持安全地编辑、级联归档和恢复学习主题，同时保留历史关联数据并阻止新的归档主题关联。

**Architecture:** 将归档、恢复、父主题合法性、排序和影响统计放入 `src/data-model.js` 的纯函数，先由 Node 自动测试覆盖。`src/app.js` 只负责保存数据、调用数据模型和渲染交互；HTML/CSS 只增加主题治理入口和状态展示。归档只修改主题记录的归档字段，不改写资料、计划、笔记或进度记录的 `topicId`。

**Tech Stack:** 原生 HTML、CSS、浏览器 JavaScript、Local Storage、Node.js 内置 `node:test`。

**Spec:** `docs/v1.1-p2-p0-topic-governance-requirements.md`

## Global Constraints

- 不实现主题直接删除、永久删除、回收站、批量归档或批量恢复。
- 归档父主题时，必须级联归档全部子孙主题；只允许从归档组顶层主题恢复。
- 归档不得修改已有资料、计划、笔记、进度记录的 ID、内容或 `topicId`。
- 已归档主题不能用于新建资料、计划、笔记、进度，也不能成为其他主题的新父主题。
- 既有资料、笔记、进度可编辑自身内容；其归档主题关联只读保留。计划只保留既有的完成/取消完成操作，不新增计划编辑。
- 学习方向不可编辑；主题改父级时不可形成自身或子孙节点循环。
- 保持 Local Storage 向后兼容：旧主题缺少归档字段时必须视为未归档，且页面启动不得自动覆盖异常旧数据。
- 每个任务完成后运行对应测试；最终在独立浏览器资料目录完成页面回归，并检查 390px 宽度无横向溢出。

## 最终验收标准

- 主题可安全编辑名称、状态和父主题，学习方向保持不变且不产生循环。
- 归档父主题会归档所有子孙主题；确认提示准确展示影响数量；不删除历史数据。

- 只能从归档组根主题恢复整组主题；恢复后可正常编辑和新建关联。
- 所有自动测试、语法检查、页面回归和用户验收均有记录，项目状态文档在验收后更新。
