# V1.3 AI 辅助学习进度草稿 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让用户输入一段自由学习描述，由可替换的 Mock AI Provider 生成可编辑的学习进度草稿，并且只有在用户确认后才沿用现有逻辑保存记录。

**Architecture:** 新增 `MockAIProvider` 负责无副作用的规则解析，新增 `AIService` 作为页面调用任何 Provider 的唯一异步入口并验证统一返回结构。页面只调用 `AIService.generateProgressDraft()`，把成功草稿填入现有进度表单；最终保存继续经过现有校验与 Local Storage 写入逻辑，因此学习进度数据结构不变。

**Tech Stack:** 原生 HTML、CSS、浏览器 JavaScript、IIFE/UMD 风格模块、Local Storage、Node.js 内置 `node:test`、Playwright 页面回归测试；不新增运行时依赖、服务器或真实 AI API。

**Spec:** `docs/v1.3-ai-assisted-progress-draft-requirements.md`

## Global Constraints

- 保持 `generateProgressDraft({ description, referenceDate, context: { directions, topics, resources, plans } })` 接口和 `{ draft, missingFields, warnings }` 返回结构。
- `draft` 始终包含 `date`、`topicId`、`resourceId`、`planId`、`durationMinutes`、`completionPercent`、`reflection`；无法识别的字段为 `null`，空总结为 `""`。
- 页面必须让用户检查日期、学习主题、关联资料、学习计划、实际时长、完成度和简短总结这七项内容。
- 当前只使用确定性 Mock Provider；不得接入 OpenAI、DeepSeek 或其他真实 API。
- 不新增 API Key、模型配置、服务器、云部署、网络请求或运行时依赖。
- 不新增或修改学习进度字段，不执行 Local Storage 迁移，不新增 `learningContent`。
- Provider 和 AI Service 不读写 DOM 或 Local Storage，也不修改传入的方向、主题、资料和计划。
- 只能关联已有活动主题、已有资料和符合现有日期规则的计划；不自动创建或修改业务数据。
- 未经用户点击“确认并保存”，不得写入学习进度。
- 手动新增、编辑、删除、历史补录、归档保护、100% 不联动等既有规则保持不变。
- 每个实现任务先写失败测试，再作最小实现并验证；最终执行全量测试、语法检查、390px 页面回归和差异检查。
- Git 暂存前检查 `.gitignore` 和文件范围，不加入 `.env`、Key、Token、浏览器资料目录或无关文件。

- [ ] **Step 3: 建立双环境 Provider 外壳**

使用与 `src/data-model.js` 一致的 IIFE 形式：

```js
(function attachMockAIProvider(globalScope) {
  const DRAFT_FIELDS = [
    "date", "topicId", "resourceId", "planId",
    "durationMinutes", "completionPercent", "reflection",
  ];

  async function generateProgressDraft(request) {
    const description = typeof request?.description === "string" ? request.description.trim() : "";
    const context = normalizeContext(request?.context);
    const parsed = parseProgressDraft(description, request?.referenceDate, context);
    const draft = parsed.draft;
    return {
      draft,
      missingFields: DRAFT_FIELDS.filter((field) => draft[field] === null || draft[field] === ""),
      warnings: parsed.warnings,
    };
  }

  const api = { generateProgressDraft };
  globalScope.MockAIProvider = api;
  if (typeof module !== "undefined" && module.exports) module.exports = api;
})(typeof window !== "undefined" ? window : globalThis);
```

`normalizeContext` 对非数组输入回退为空数组但不修改原数组。`parseProgressDraft` 返回 `{ draft, warnings }`，始终建立七个草稿键，并在解析时记录日期非法、候选歧义和关联失败的具体提示；总结为裁剪后最多 500 字的描述。

- [ ] **Step 3: 实现 Provider 注入与统一校验**

```js
const DRAFT_FIELD_RULES = {
  date: (value) => value === null || typeof value === "string",
  topicId: (value) => value === null || typeof value === "string",
  resourceId: (value) => value === null || typeof value === "string",
  planId: (value) => value === null || typeof value === "string",
  durationMinutes: (value) => value === null || (Number.isInteger(value) && value > 0),
  completionPercent: (value) => value === null || (Number.isInteger(value) && value >= 0 && value <= 100),
  reflection: (value) => typeof value === "string" && value.length <= 500,
};

function createAIService(provider) {
  if (!provider || typeof provider.generateProgressDraft !== "function") {
    throw new Error("AI Provider 未实现 generateProgressDraft。");
  }
  return {
    async generateProgressDraft(request) {
      return validateProgressDraftResult(await provider.generateProgressDraft(request));
    },
  };
}
```

`validateProgressDraftResult` 验证：结果为对象；`draft` 有七个自有键且符合类型规则；`missingFields` 只含合法字段名；`warnings` 为字符串数组。失败统一抛出 `Error("AI Provider 返回了无效的学习进度草稿。")`。
