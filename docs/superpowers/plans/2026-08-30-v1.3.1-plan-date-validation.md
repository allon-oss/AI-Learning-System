# V1.3.1 Historical Plan Backfill Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Preserve today/future-only ordinary plans while allowing an explicit historical-backfill mode to create marked plans for past dates and link past progress without rewriting the plan date.

**Architecture:** Extend the existing plan record with one backward-compatible boolean, `isBackfilled`, normalized to `false` for legacy data. The existing plan form gets an explicit entry-mode selector; one shared validator applies ordinary-plan or backfill date rules, while the existing progress form and `planId` linkage remain unchanged.

**Tech Stack:** Static HTML, vanilla JavaScript, CSS, Local Storage, Node.js test runner, Playwright with local Microsoft Edge.

**Spec:** `docs/superpowers/specs/2026-08-22-v1-1-requirements-design.md` sections 4.1 and 4.2, plus the user-confirmed 2026-08-30 historical-backfill rules in this task.

## Global Constraints

- Ordinary plans allow only today or future dates.
- Historical-backfill plans allow only dates before today and store the selected historical date unchanged.
- Historical-backfill plans are visibly marked as “事后补录” and appear in History even when `isCompleted` is `false`.
- Progress records continue to allow only today or past dates; future progress remains forbidden.
- Plan and progress date constraints refresh when the page remains open across local midnight.
- Saving progress must not rewrite the linked plan's `date` or automatically change its `isCompleted` value.
- Old plans without `isBackfilled` normalize to `false`; no Local Storage migration is added.
- Plan and progress remain two separate saves. Do not add combined saving, multi-topic entry, AI plan creation, automatic rollover, duplicate merging, or plan-status expansion.
- Do not update `docs/project-status.md`, commit, merge, or start V1.4 until the user completes manual acceptance.
