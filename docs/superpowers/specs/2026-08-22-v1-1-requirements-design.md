# AI-Learning-System V1.1 需求确认文档

## 1. 文档目的

本文档用于确认 AI-Learning-System V1.1 的开发范围，作为后续开发、测试和验收的共同依据。

V1.1 不重做 V1 已有的学习闭环，继续围绕五个核心模块展开：

- 学习主题：我正在学习什么。
- 学习资料：我使用什么资料学习。
- 学习计划：我准备完成什么任务。
- 学习笔记：我学到了什么。
- 学习进度：我实际学习了多久、完成了多少。

本版本优先解决 Day1–Day3 真实测试中出现的状态理解和主题排序问题，再补齐连续多日使用、数据安全和基础回看能力。

## 2. 产品原则与统一规则

### 2.1 状态定义

- **资料整体状态**：描述整份资料长期处于未开始、学习中、暂停或已完成。
- **任务完成状态**：描述某一天的一项具体任务是否完成。
- **单次进度完成度**：描述一次学习记录完成了多少，范围为 0–100%。
- 三种状态互相独立，不能因为完成一次任务就自动把整份资料改为“已完成”。

### 2.2 数据原则

- 继续使用浏览器 Local Storage，不增加后端和账号系统。
- 现有主题、资料、计划、笔记和进度数据必须继续可读。
- 新字段缺失时使用安全默认值，不要求用户手动迁移旧数据。
- 删除、导入覆盖等可能造成数据损失的操作必须提前说明影响并要求确认。

### 2.3 发布范围

- P0 和 P1 是 V1.1 的必做范围。
- P2 是 V1.1 的增强范围；如果影响 P0/P1 稳定性，可以整体或逐项延期到 V1.2。
- 每完成一个优先级，都要重新执行 Day1、Day2、Day3 测试场景。

## 3. P0 需求：解决真实使用反馈

### 3.1 数据兼容与测试基线

阶段执行说明：第一阶段按用户最新确认只实现状态语义区分和主题稳定排序。本节中的计划、资料默认字段和备份校验测试保留为后续 P1/P2 前置要求；P0 分支只实现主题兼容、排序规则和资料今日任务摘要所需测试。

#### 具体需求

- 建立不依赖第三方库的最小自动测试环境。
- 将排序、字段默认值、日期分类、备份校验等纯数据规则放入独立的数据模块。
- 覆盖旧主题、旧计划和旧资料在新增字段后的兼容行为。
- 页面加载数据模块失败时不得继续执行可能修改本地数据的操作。

#### 用户使用场景

用户已经在 V1 中保存了主题、资料、计划、笔记和进度。升级到 V1.1 后，原有数据正常显示，不需要重新创建，也不会因为缺少新字段而消失。

#### 修改模块

- 全局数据加载与保存。
- 学习主题数据。
- 学习资料数据。
- 学习计划数据。
- 学习进度数据。
- 新增数据规则测试模块。

#### 不包含

- 不引入 React、Vue 等前端框架。
- 不引入数据库或服务器。
- 不对 `src/app.js` 做无关的大规模重构。
- 不改变现有五类 Local Storage key。

#### 验收标准

- 使用 V1 数据打开 V1.1，五个模块均可正常显示和操作。
- 自动测试可以验证旧数据默认值和核心数据规则。
- 浏览器控制台没有数据迁移错误。

### 3.2 区分资料、任务和进度状态

#### 具体需求

- 资料表单和详情中的“学习状态”统一改为“资料整体状态”。
- 计划卡片明确显示“今日任务状态”。
- 完成任务后显示“今日任务已完成并保存”的非阻断反馈。
- 取消完成后显示“已取消任务完成状态”的非阻断反馈。
- 资料详情增加“今日关联任务”摘要，显示当日关联任务数量和完成数量。
- 资料详情继续单独显示关联进度记录，不用任务完成数量替代进度。
- 完成任务不得自动修改资料整体状态。

#### 用户使用场景

用户用一份处于“学习中”的 YouTube 课程完成当天观看任务。任务显示已完成，资料仍显示“资料整体状态：学习中”，同时资料详情显示“今日关联任务：已完成 1/1”。用户能够确认任务已经保存，并理解课程整体还没有学完。

#### 修改模块

- 学习资料表单和详情。
- 今日计划列表和完成按钮。
- 资料与计划的关联统计。
- 状态提示样式。
- 主题详情中的关联摘要文案。

#### 不包含

- 不自动修改资料整体状态。
- 不把计划状态和进度完成度合并成一个字段。
- 不增加复杂通知中心。
- 不使用弹窗打断正常的完成操作。

#### 验收标准

- Day1、Day2 场景中，用户可以直接区分资料状态与任务状态。
- 完成和取消完成都有明确保存反馈。
- 资料整体状态在完成任务前后保持不变。

### 3.3 主题稳定排序

#### 具体需求

- 每个主题增加稳定的排序值。
- 用户可以通过“上移”和“下移”调整主题顺序。
- 排序只在同一学习方向、同一父主题范围内生效。
- 第一项不能继续上移，最后一项不能继续下移。
- 新建主题默认放在当前同级列表末尾，不能打乱已有学习路线。
- 刷新页面或重新打开浏览器后保留排序结果。
- 旧主题第一次加载时按当前显示顺序生成排序值。

#### 用户使用场景

用户希望将 AI 学习路线整理为“AI 基础 → Prompt Engineering → AI 工作流 → AI 产品设计”。新增“AI 产品设计”后，它出现在同级列表末尾；用户可以通过上移、下移进一步调整，刷新后顺序不变。

#### 修改模块

- 学习主题新增。
- 学习主题列表渲染。
- 父子主题和学习方向分组。
- 主题 Local Storage 数据兼容。
- 主题卡片操作区域和样式。

#### 不包含

- V1.1 不做拖拽排序。
- 不允许主题跨学习方向移动。
- 不允许通过排序按钮改变父子关系。
- 不自动根据创建时间、名称或学习难度重新排序。

#### 验收标准

- Day3 中的学习路线能够按预期排列。
- 调整一个主题不会改变其他学习方向或其他父主题下的顺序。
- 新增主题和刷新页面都不会破坏已有顺序。

## 4. P1 需求：连续使用与数据安全

### 4.1 按日期创建和回看学习计划

#### 具体需求

- 创建计划时允许选择日期，默认值为当天。
- 计划增加可选预计时长，单位为分钟，只接受正整数。
- 计划增加高、中、低三个优先级，默认值为“中”。
- 计划页面分为今天、未来和历史三个视图。
- 过去日期中仍未完成的任务显示“已逾期”。
- 今天的未完成任务不显示逾期。
- 未来计划不能出现在今天的任务统计中。
- 历史计划保留完成状态、主题、资料、预计时长和优先级。
- 旧计划继续使用原有日期，缺少优先级时按“中”处理，缺少预计时长时显示为未设置。

#### 用户使用场景

用户周日提前安排下周一的雅思词汇任务。周一打开系统时，该任务自动出现在今天视图。如果到周二仍未完成，它会进入历史视图并标记为逾期。

#### 修改模块

- 学习计划创建表单。
- 学习计划数据结构。
- 今天、未来、历史计划列表。
- 主题详情中的今日计划统计。
- 计划与资料、主题的关联选项。

#### 不包含

- 不做周历、月历或拖拽日历。
- 不做重复任务。
- 不做系统通知和提醒。
- 不与第三方日历同步。
- 不自动把逾期任务移动到今天。

#### 验收标准

- 用户可以创建今天和未来日期的计划。
- 今天、未来、历史分类准确。
- 旧计划仍然可见。
- 逾期状态不会改变任务原始日期。

### 4.2 进度补录与计划联动

#### 具体需求

- 新增进度时允许选择实际学习日期，默认值为当天。
- 进度日期不能晚于当天。
- 编辑进度时默认保留原记录日期，用户可改为其他不晚于当天的日期。
- 进度只能关联同一主题下、计划日期不晚于实际学习日期的计划；默认关联列表优先显示日期最接近的计划。
- 当关联计划尚未完成且本次进度为 100% 时，保存后提供两个明确选项：“同时完成计划”和“仅保存进度”。
- 用户选择“仅保存进度”时，计划状态保持不变。
- 已完成计划如果没有关联进度，显示“尚未记录实际学习”，但不强制补录。
- 任何联动都不得修改资料整体状态。

#### 用户使用场景

用户昨天完成了学习，但忘记记录。今天补录昨天的 45 分钟进度并选择完成度 100%。系统询问是否同时完成昨天关联的计划；用户可以同步完成，也可以仅保存进度。

#### 修改模块

- 学习进度新增和编辑表单。
- 进度日期校验。
- 计划关联选项。
- 计划卡片进度摘要。
- 计划完成状态。
- 资料整体状态保护规则。

#### 不包含

- 不根据学习时长自动计算完成度。
- 不强制 100% 进度同步完成计划。
- 不根据计划完成自动生成进度记录。
- 不修改资料整体状态。
- 不允许记录未来日期的实际进度。

#### 验收标准

- 用户可以准确补录过去日期。
- 100% 进度只触发提示，不强制同步。
- 80% 或无关联计划的进度不会触发计划完成提示。
- 编辑旧进度不会自动改成当天日期。

### 4.3 本地数据导出与安全恢复

#### 具体需求

- 一次导出主题、资料、计划、笔记和进度五类数据。
- 备份文件包含格式版本、导出时间和五类数据数组。
- 导出文件名包含产品名称和本地日期。
- 导入时先解析和校验文件，不允许校验失败的数据进入 Local Storage。
- 导入预览必须显示五类数据各自的记录数量。
- V1.1 导入只支持“整体覆盖”，不支持合并。
- 用户确认覆盖前，系统先自动下载当前数据快照。
- 用户取消确认时不得修改任何本地数据。
- 导入成功后重新加载并显示恢复后的数据。

#### 用户使用场景

用户准备清理浏览器数据或更换浏览器，先导出完整备份。在新环境选择备份文件，确认五类数据数量无误后执行恢复。

#### 修改模块

- 全部五类 Local Storage 数据。
- 新增数据备份入口。
- 文件下载和文件选择。
- 备份格式校验。
- 覆盖确认和结果反馈。

#### 不包含

- 不做云端备份。
- 不做账号同步。
- 不做两份备份的自动合并。
- 不导入未知版本或结构不完整的文件。
- 不上传备份文件到任何外部服务。

#### 验收标准

- 导出的文件可以在清空数据后完整恢复五类记录。
- 损坏文件、错误版本和缺少数据数组的文件都会被拒绝。
- 导入取消或校验失败时，原数据完全不变。
- 覆盖前能获得一份可恢复的当前数据快照。

## 5. P2 需求：完善管理与回看

### 5.1 资料来源和学习位置

#### 具体需求

- 资料增加可选的来源名称、来源链接、学习位置和备注。
- 来源链接仅允许 `http:` 和 `https:` 协议成为可点击链接。
- 非法或其他协议不允许保存为可点击链接，并显示明确校验反馈。
- 学习位置使用自由文本，可记录视频时间、课程章节、PDF 页码或纸质资料位置。
- 编辑资料时完整回填新增字段。
- 旧资料的新增字段默认为空。

#### 用户使用场景

用户添加一段 YouTube 课程，保存原始链接，并记录“已看到 23:40”；下次可以从资料详情返回视频并继续学习。

#### 修改模块

- 学习资料新增和编辑表单。
- 学习资料数据结构。
- 学习资料详情。
- 主题详情中的资料入口。

#### 不包含

- 不上传 PDF、视频或图片文件。
- 不自动抓取网页标题、封面或正文。
- 不做 OCR。
- 不做 AI 自动摘要。
- 不为同一资料保存多个来源链接。

#### 验收标准

- YouTube、网页、PDF 页码和纸质资料位置均可记录。
- 安全链接可以打开，非法协议不会变为可点击链接。
- 编辑和刷新后字段保持不变。

### 5.2 主题归档与删除影响提示

#### 具体需求

- 主题支持编辑名称、学习方向、父主题、描述和主题状态。
- 主题支持归档和取消归档。
- 默认主题列表和新增关联选项不显示已归档主题。
- 提供单独入口查看已归档主题。
- V1.1 不提供主题永久删除，避免破坏大量关联数据。
- 删除资料前显示关联计划、笔记和进度数量。
- 删除计划前显示关联笔记和进度数量。
- 删除确认必须明确说明历史记录会保留，但关联名称会显示为已删除。
- 用户可以取消删除并返回原页面，不产生数据修改。

#### 用户使用场景

用户不再学习某个旧主题，但希望保留历史笔记和进度，因此将主题归档。删除某份重复资料时，系统先提示它关联了 2 条笔记和 3 条进度，用户据此决定取消或继续删除。

#### 修改模块

- 学习主题详情和编辑。
- 主题列表、归档列表及各关联选择器。
- 学习资料删除。
- 学习计划删除。
- 学习笔记和进度中的已删除关联显示。

#### 不包含

- 不永久删除主题。
- 不自动把关联数据迁移到其他主题、资料或计划。
- 不批量归档或批量删除。
- 不恢复已经永久删除的资料或计划。

#### 验收标准

- 归档主题不出现在默认列表和新关联选项中，但历史记录仍能显示主题名称。
- 取消归档后主题恢复到原有排序位置。
- 删除资料或计划前的关联数量准确。
- 取消删除不会改变任何数据。

### 5.3 基础筛选与学习回看

#### 具体需求

- 学习进度页支持按主题筛选。
- 选择主题后，资料和计划筛选项只显示该主题相关内容。
- 支持按资料、计划和日期范围筛选。
- 日期范围包含开始日期和结束日期当天。
- 所有筛选条件可以组合使用。
- 提供“清除筛选”按钮。
- 页面显示筛选后的记录数量和累计学习时长。
- 没有匹配结果时显示明确空状态，不删除或修改原记录。

#### 用户使用场景

用户想回看过去一个月学习“雅思词汇”的时间和完成情况，选择主题与日期范围后，只看到相关进度记录及累计时长。

#### 修改模块

- 学习进度列表。
- 主题、资料和计划关联数据。
- 进度累计统计。
- 筛选控件和空状态。

#### 不包含

- 不做全局全文搜索。
- 不搜索笔记正文。
- 不做图表、热力图和连续打卡。
- 不生成周报、月报或 AI 总结。
- 不保存多套筛选方案。

#### 验收标准

- 单条件和组合条件结果准确。
- 清除筛选后恢复全部记录。
- 筛选不会修改或删除原数据。
- 已删除关联项的历史进度仍可以通过日期范围回看。

## 6. V1.1 全局不包含内容

- 用户登录、多用户、权限系统。
- 后端服务、数据库和云同步。
- 手机 App。
- 第三方日历同步和系统提醒。
- 重复计划、周期计划和复杂日历。
- 全局全文搜索。
- 拖拽主题排序。
- 文件上传、OCR、自动抓取网页内容。
- 图表、热力图、周报、月报和连续学习统计。
- AI 总结、AI 规划、AI 推荐、AI 出题和 RAG 知识库。
- 自动迁移已删除对象的历史关联。
- 备份数据自动合并。

## 8. 发布确认条件

V1.1 进入发布检查前必须满足：

- P0、P1 的全部验收标准通过。
- Day1、Day2、Day3 原始测试场景全部回归通过。
- V1 现有数据升级后没有丢失或不可见记录。
- 损坏备份和取消导入不会修改本地数据。
- 删除资料或计划前能够看到准确影响范围。
- 桌面和移动端布局可用，浏览器控制台无 JavaScript 错误。
- README、功能清单和项目状态与实际完成范围一致。
- Git 提交范围经过检查，不包含敏感信息或无关文件。

## 9. 需求变更规则

- 开发中发现的新问题先记录并分类为 Bug、体验问题或新需求。
- 会扩大数据结构、增加外部服务或改变本文件“不包含内容”的需求，不直接加入当前任务。
- P0/P1 范围变更需要先更新本需求文档和开发计划，再开始实现。
- P2 功能可以延期，但不得以牺牲 P0/P1 稳定性为代价强行纳入 V1.1。
