## 1. 背景

V1.3 已支持把一段自然语言生成一条可修改的学习进度草稿，但当前 Mock Provider、AI Service 和页面表单都只处理一个 `draft`。当用户同一天学习多个主题时，仍需要分多次输入和确认。

V1.4 已完成多主题批量今日计划录入，并验证了“临时草稿不改变既有数据结构、确认后保存为独立记录”的方式。本阶段把同样的安全原则用于学习进度，但采用已经确认的“草稿队列，逐条修改并保存”交互，不提供整批保存。

## 2. 目标

- 用户只输入一段当天学习描述，系统识别其中一个或多个学习片段。
- 每个学习片段生成一条独立、可修改的进度草稿。
- 草稿按原文首次出现顺序进入队列。
- 用户可以逐条检查、修改、保存或放弃。
- 保存或放弃当前草稿，不得修改、重置或删除其他未确认草稿。
- 尽量关联已有活动主题、同主题资料和当天计划；无法唯一判断时保留空值并解释原因。
- 继续使用 Mock AI 和可替换的 AI Service/Provider 分层，不接入真实 API。
- 保存后仍生成现有结构的独立学习进度记录，不新增批次实体或持久化草稿结构。

## 3. 非目标

- 不接入 OpenAI、DeepSeek 或其他真实 AI API。
- 不配置、读取或保存 API Key、Token、密码或 Provider 配置。
- 不新增服务器、账户系统、云同步、MCP 或 Connector 权限。
- 不持久化草稿队列；刷新页面后未确认草稿可以丢失。
- 不提供“保存全部”、整批回滚、批次 ID、批次删除或批次编辑。
- 不自动创建、修改、归档或恢复主题、资料和计划。
- 不自动填写没有明确依据的实际时长或完成度。
- 不把计划预计时长当作实际学习时长。
- 不新增单词数量、题目数量、学习内容或 `learningContent` 字段。
- 不自动修改计划完成状态或资料整体状态。
- 不生成学习笔记、总结报告、学习建议、提醒或定时任务。

## 4. 名词

- **原始描述**：用户一次提交给 AI Service 的完整自然语言文本。
- **学习片段**：原始描述中能与其他学习内容区分的一段内容，例如“Codex 学了 40 分钟”。
- **草稿队列**：本次生成、尚未保存或放弃的草稿集合，只存在于当前页面内存中。
- **当前草稿**：队列中正在使用现有进度表单编辑的一条草稿。
- **建议学习方向**：Provider 能判断大方向但不能唯一确定已有主题时返回的展示信息；不写入进度记录。
- **确认保存**：用户明确提交当前草稿，且通过现有进度校验后写入一条进度记录。

## 5. 核心使用流程

1. 用户进入“学习进度”，输入一段包含一个或多个学习主题的描述。
2. 页面调用 `AIService.generateProgressDrafts()`，传入描述、参考日期和已有方向、活动主题、资料及计划。
3. Mock Provider 识别学习片段，按原文顺序返回一条或多条草稿。
4. 页面在生成结果全部通过 Service 校验后建立新的草稿队列。
5. 页面显示队列卡片，并把第一条草稿载入现有进度表单。
6. 用户修改当前草稿时，页面即时把表单值同步回当前队列项。
7. 用户可以选择其他队列项继续检查，之前的修改必须保留。
8. 用户点击“确认并保存此条”时，系统复用现有进度校验和保存规则。
9. 保存成功后只从队列移除当前草稿，并自动选中原位置的下一条；若没有下一条，则选中上一条。
10. 用户点击“放弃此条”并确认后，只移除当前草稿，不写入进度记录。
11. 队列清空后，页面恢复普通手动新增状态。

## 6. 示例行为

输入：

```text
今天 Codex 学了40分钟，背了40个单词。
```

系统应生成两条草稿，而不是把整段内容放进一条记录：

### 草稿 1

- 来源片段：`Codex 学了40分钟`
- 建议方向：`AI 学习`
- 主题：若存在唯一的 Codex 相关活动主题或唯一的当天 Codex 计划，则关联对应主题；否则留空。
- 实际时长：`40`
- 完成度：空，等待用户补充。
- 总结：保留 Codex 学习内容。

### 草稿 2

- 来源片段：`背了40个单词`
- 建议方向：`雅思英语学习`
- 主题：优先关联已有“词汇”主题；不能唯一确定时留空。
- 实际时长：空；“40个单词”是学习数量，不得误填为 40 分钟。
- 完成度：空，等待用户补充。
- 总结：保留背单词数量信息。

如果对应主题当天只有一条有效计划，草稿可以自动关联该计划；如果有多条当天计划且描述不能唯一匹配，计划保持为空。

## 7. 多主题拆分规则

### 7.1 基本原则

- 标点是允许的切分位置，但不能简单按所有逗号切分。
- 只有发现新的主题、方向、资料或计划线索时，才开始新的学习片段。
- 同一主题的资料、计划、时长、完成度和总结说明应保留在同一片段中。
- 返回顺序必须与各学习片段第一次出现在原文中的顺序一致。
- Provider 不得改变传入的上下文对象或数组。

### 7.2 强边界

句号、分号、换行、问号和感叹号作为强边界候选。强边界两侧如果都包含学习内容，则分别解析。

### 7.3 逗号与连接词

逗号、顿号以及“然后”“另外”“还”“接着”等只能作为弱边界。出现以下情况之一时才切分：

- 边界后出现与当前片段不同的完整活动主题名称。
- 边界后出现另一个学习方向名称。
- 边界后出现能唯一反推另一个主题的资料或当天计划。
- 边界后出现受控的方向提示词，且与当前片段方向不同。

例如 V1.3 的“学习 Transformer、使用注意力机制视频、完成看完第二章计划”仍是一条草稿，因为资料和计划属于同一主题。

### 7.4 不确定拆分

- 不能可靠拆分时宁可保留较大的片段并给出提示，不得凭数组顺序猜测。
- 完全无法识别主题或方向，但文本明显包含独立学习行为时，仍可生成主题为空的草稿，避免丢失用户内容。
- 空片段、只有日期或只有连接词的片段不得生成草稿。
- 一次返回最多 10 条草稿；超过时只返回前 10 条，并在顶层提示用户拆分描述后再次生成。

## 8. Mock Provider 匹配规则

### 8.1 日期

- 识别明确的 `YYYY-MM-DD`、“今天”“今日”“昨天”和“昨日”。
- 原始描述开头的公共日期可以继承给没有独立日期的后续片段。
- 没有日期时使用调用时的 `referenceDate`。
- 未来或无效日期保持为空并提示，不得静默改成今天。
- 已生成草稿跨过午夜后不自动改写日期；保存时继续使用现有日期校验。

### 8.2 主题和方向

主题关联按以下优先级执行：

1. 片段中完整出现的活动主题名称，最长唯一候选优先。
2. 片段中完整出现的当天计划任务，由唯一计划反推主题。
3. 片段中完整出现的资料标题，由唯一资料反推主题。
4. 学习方向名称用于缩小候选范围。
5. Mock 的受控提示词只用于建议方向或寻找明显同义主题，不越过歧义保护。

第一阶段受控提示词仅覆盖验收所需的明确表达：

- `Codex`、`ChatGPT`、`OpenAI`、`RAG`、`Prompt`、`大模型`提示 `AI 学习`。
- `雅思`、`IELTS`、`单词`、`背词`提示 `雅思英语学习`。
- `单词`、`背词`可以在雅思方向内匹配名称为“词汇”的唯一活动主题。

如果方向内只有一个活动主题，可以自动选择；如果存在多个主题而没有更具体线索，`topicId` 保持为空，仅展示建议方向。

### 8.3 当天计划

- 优先考虑 `plan.date === draft.date` 的同主题有效计划。
- 片段完整包含任务名称且候选唯一时自动关联。
- 没有完整任务名称，但该主题在草稿日期只有一条有效计划时，可以自动关联唯一计划。
- 同一天存在多条计划且无法唯一判断时保持为空。
- 只有描述明确提到任务名称时，才允许关联早于草稿日期的其他合规计划。
- 归档主题计划、未来计划、其他主题计划和日期异常计划不得关联。

### 8.4 资料

- 主题已经确定时，只在同主题资料中匹配。
- 完整标题唯一匹配时自动关联。
- 多个资料同时出现或候选不唯一时保持为空。
- 不根据资料类型或数组顺序猜测。

### 8.5 实际时长与其他数量

- 只识别带时间单位的数字，例如“40 分钟”“1.5 小时”。
- 小时换算为正整数分钟；无效、负数、零或无法整分换算时保持为空。
- “40 个单词”“20 道题”“3 章”“2 个视频”等不是实际时长，只保留在总结中。
- 同一片段多个合法时长相加；跨片段时长不得互相借用或平均分配。
- 公共总时长无法可靠分配给多个主题时，各草稿时长保持为空并提示用户补充。

### 8.6 完成度

- 只识别片段内明确的 `0%` 至 `100%` 整数百分比。
- 不把数量、计划状态或“学完了”等文字自动换算成百分比。
- 同一片段出现多个不同百分比时保持为空并提示歧义。
- 原始描述末尾的公共百分比不能自动复制给多个主题，除非文字明确表达“都完成 80%”。Mock 第一阶段不实现这类公共分配，统一提示手动补充。

### 8.7 简短总结

- 每条草稿只使用自己的来源片段生成 `reflection`。
- 保留单词数、题目数、章节数等不能写入结构化字段的信息。
- 最长 500 字，超出时按现有规则截断并提示。
- 原始完整描述和来源片段都不单独持久化。

## 9. AI Service/Provider 接口

### 9.1 请求

```text
generateProgressDrafts({
  description,
  referenceDate,
  context: {
    directions,
    topics,
    resources,
    plans
  }
})
```

页面仍只能通过 AI Service 调用 Provider，不得直接调用 Mock 内部解析函数。

### 9.2 返回

```text
{
  drafts: [
    {
      sourceText,
      suggestedDirection,
      draft: {
        date,
        topicId,
        resourceId,
        planId,
        durationMinutes,
        completionPercent,
        reflection
      },
      missingFields,
      warnings
    }
  ],
  warnings
}
```

约束：

- `drafts` 必须包含 1–10 条合法草稿。
- `sourceText` 是非空字符串，最长 500 字。
- `suggestedDirection` 为已有方向字符串或 `null`，只用于展示。
- 每个 `draft` 继续包含 V1.3 的全部七个字段。
- `missingFields` 只使用七个草稿字段名。
- 草稿级 `warnings` 解释当前片段的问题；顶层 `warnings` 解释整体拆分、截断或描述级问题。
- AI Service 必须拒绝未知键、错误类型、空数组、超过 10 条、非上下文已有方向和非法字段值。
- Service 或 Provider 异常不得覆盖现有队列和当前表单。

### 9.3 接口迁移

- `generateProgressDrafts()` 是 V1.5 的正式接口。
- 实施期间可以暂时保留 V1.3 `generateProgressDraft()` 作为迁移适配，但页面迁移完成后必须删除旧入口及旧测试依赖，避免未来 Provider 同时维护两套契约。
- 未来真实 Provider 只需要实现同一 `generateProgressDrafts()` 输入输出约定。

## 10. 草稿队列状态

每个页面队列项包含：

```text
{
  id,
  sourceText,
  suggestedDirection,
  draft,
  providerMissingFields,
  warnings
}
```

- `id` 由页面队列模块生成，只用于当前会话，不写入进度记录。
- `draft` 是用户可修改的当前值。
- `providerMissingFields` 保留 AI 初始识别结果，用于解释生成质量。
- 页面必须根据用户修改后的 `draft` 重新计算当前缺失字段，不能一直显示已经补齐的字段仍然缺失。
- 队列状态更新使用新数组和新对象，不原地修改 Provider 返回结果。

## 11. 页面与交互

### 11.1 队列展示

- AI 区域在生成后显示“共 N 条，待处理 N 条”。
- 每条卡片显示顺序号、主题或建议方向、来源片段、时长、完成度和缺失状态摘要。
- 当前草稿使用选中样式和 `aria-current="true"`。
- 卡片按钮有明确可访问名称，例如“编辑第 2 条草稿：雅思英语学习”。
- 队列顺序不可拖动；第一阶段不提供排序和合并。

### 11.2 修改与切换

- 当前草稿继续使用现有进度表单编辑全部七个字段。
- 表单 `input` 和 `change` 后同步当前队列项。
- 切换草稿前再次同步当前表单，确保最后一次输入不会丢失。
- 切换只更新当前表单，不修改其他队列项。
- 修改日期或主题后，资料和计划继续使用现有联动规则；不兼容的选择应清除并在队列项中同步。

### 11.3 保存当前草稿

- 队列状态下按钮显示“确认并保存此条”。
- 继续使用现有日期、主题、时长、完成度、资料和计划校验。
- 校验失败时保留全部队列项和当前修改，聚焦错误字段并显示原因。
- 持久化失败时内存进度列表、Local Storage 和草稿队列均保持不变。
- 保存成功后新增一条现有结构进度记录，只移除当前队列项。
- 下一条选择规则：优先选择移除位置的新项目；没有时选择上一条。
- 最后一条保存成功后清空队列状态和原始描述，恢复“保存进度”。

### 11.4 放弃当前草稿

- 按钮显示“放弃此条”。
- 操作前确认将丢失当前未保存修改。
- 确认后只移除当前队列项，不写入或删除任何进度记录。
- 取消确认时队列和表单完全不变。
- 放弃最后一条后恢复普通手动新增状态。

### 11.5 重新生成

- 队列非空时点击重新生成，先确认是否用新结果替换全部未确认草稿。
- 用户取消时不调用 Service。
- 用户确认后，旧队列在新结果成功且通过 Service 校验前继续保留。
- 新结果成功后一次替换旧队列；失败时旧队列、当前草稿和原始描述保持不变。
- 生成期间禁用生成按钮，使用请求令牌阻止过期结果覆盖较新状态。

### 11.6 编辑已有进度

- AI 队列只用于新增进度，不用于编辑已有记录。
- 进入已有进度编辑前，先把当前表单同步回队列。
- 编辑期间隐藏草稿队列和 AI 生成操作，但队列保留在页面内存。
- 保存或取消已有进度编辑后，恢复原队列和原当前草稿。
- 编辑已有进度不得清空、重排或保存任何队列项。

### 11.7 手动新增

- 队列为空时，现有手动新增流程完全不变。
- 队列非空时，现有表单作为当前草稿编辑器；第一阶段不增加“同时手动新增”模式。
- 用户需要回到手动新增时，可以逐条保存或放弃队列草稿。

## 12. 保存与数据规则

最终保存的每条记录继续使用现有结构：

```js
{
  id,
  date,
  topicId,
  resourceId,
  planId,
  durationMinutes,
  completionPercent,
  reflection,
  createdAt,
  updatedAt
}
```

- 不新增 `batchId`、`sourceText`、`suggestedDirection`、`providerMissingFields` 或 `learningContent`。
- 每次确认只创建一条记录并写入现有 `personal-learning-system-progress-records`。
- 保存 100% 完成度仍不修改计划 `isCompleted` 或资料 `status`。
- 已保存记录与未确认草稿完全独立；后续编辑或删除记录不影响队列。
- 保存必须先构建 `nextProgressRecords`，成功写入后再替换内存数组，避免存储失败造成内存与 Local Storage 不一致。

## 13. 错误处理

- 描述为空：不调用 Service，队列不变。
- Provider 抛错或返回非法结构：显示失败提示，旧队列和表单不变。
- 没有识别到任何有效学习片段：Service 返回失败，由页面提示用户改写描述，不建立空队列。
- 草稿主题为空：允许进入队列，但保存前要求用户选择活动主题。
- 草稿关联主题在生成后被归档：保存时拒绝当前草稿，其他草稿不变。
- 资料或计划在生成后被删除：清除当前不合法关联并提示，不删除草稿。
- 日期跨午夜：新生成使用新的本地今天；已有草稿日期不自动改写。
- 同一草稿重复点击保存：保存期间禁用按钮，只允许产生一条记录。
- 切换、放弃、编辑已有记录和重新生成都必须使过期异步请求失效。

## 14. 兼容性与安全

- 保持进度、主题、资料和计划 Local Storage 键不变。
- 不执行数据迁移，不改变旧记录。
- V1.3 单主题描述必须作为一条队列草稿继续正常工作。
- V1.3 的失败保护、确认前不保存、可修改、归档保护、100% 不联动和编辑隔离继续保留。
- V1.3.1 的历史进度日期和计划关联规则继续保留。
- V1.4 批量计划页面和数据模型不与本阶段混合修改。
- 不新增 npm 依赖、网络请求或敏感配置。
- `.gitignore` 不得弱化对 `.env`、Token、密钥和本地配置的保护。
- 390px 宽度下队列、表单和按钮不得产生横向溢出。

## 15. 自动测试范围

### 15.1 Mock Provider

- 单主题输入返回一条草稿。
- 示例输入按顺序返回 Codex 和雅思词汇两条草稿。
- V1.3 同主题资料和计划描述不被错误拆成多条。
- 识别强边界、弱边界、公共日期和无法可靠拆分的情况。
- 只把带时间单位的数字作为时长，不把单词数或题目数当成分钟。
- 按主题、当天计划、资料、方向和受控提示词优先级匹配。
- 多主题、同名主题、多个当天计划和多个百分比时保护歧义。
- 最多返回 10 条，并提示截断。
- 不修改输入上下文。

### 15.2 AI Service

- 委托 `generateProgressDrafts()` 并保持异步接口。
- 接受 1–10 条完整合法草稿。
- 拒绝空数组、超限数组、未知键、非法方向、非法字段和错误警告。
- Provider 异常保持 Promise 拒绝。
- 浏览器默认实例继续使用 Mock Provider。

### 15.3 队列状态模块

- 建立稳定顺序和会话 ID。
- 更新一条时不修改其他条目或输入数组。
- 删除当前项后正确选择下一条或上一条。
- 根据修改后的字段重新计算缺失项。
- Provider 原始对象不被页面状态修改。

### 15.4 页面流程

- 生成两条后按原文顺序显示并载入第一条。
- 切换草稿保留两条各自的修改。
- 保存第一条后 Local Storage 只增加一条，第二条保持原值并成为当前草稿。
- 放弃一条不保存、不改变其他草稿。
- 当前草稿校验失败或存储失败时全部未确认草稿保留。
- 重新生成取消、成功和失败分别符合替换规则。
- 编辑已有进度期间队列隐藏但保留，退出后恢复。
- 单主题 AI 草稿、普通手动新增和已有进度编辑继续工作。
- 重复点击、过期请求、归档主题、删除关联、跨午夜和 390px 回归通过。
- 页面无未处理 JavaScript 错误。

### 15.5 安全与范围

- 源码不存在真实 API 请求、API Key、Authorization 或 Bearer 凭据。
- 进度记录不包含队列元数据或 `learningContent`。
- `.gitignore`、`package.json` 和 V1.4 批量计划数据结构未被无关修改。
- Git 提交按 Provider/Service、队列模块、页面流程和文档收尾分开保存。

## 16. 人工验收

1. 准备 AI 与雅思两个活动主题，并为它们分别准备当天计划。
2. 输入“今天 Codex 学了40分钟，背了40个单词。”，确认生成两条且顺序正确。
3. 确认“40个单词”没有被填成 40 分钟，两条完成度都保持为空。
4. 分别补充两条完成度和雅思实际时长，来回切换确认修改不丢失。
5. 保存 Codex 草稿，确认只新增一条进度，雅思草稿仍存在且内容不变。
6. 放弃雅思草稿，确认没有新增第二条记录。
7. 再次生成两条，保存第二条前让第一条校验失败，确认两条草稿都仍存在。
8. 测试重新生成的取消、失败和成功替换，确认失败不会丢失旧队列。
9. 队列存在时编辑一条已有进度并退出，确认队列恢复且修改保留。
10. 测试主题歧义、多个当天计划、归档主题、删除资料或计划和未来日期。
11. 刷新页面，确认已保存进度仍存在，未保存队列不再出现。
12. 在 390px 宽度完成生成、切换、修改、保存和放弃，无横向滚动或控制台错误。

## 17. 完成标准

- 一段描述可以生成 1–10 条有序、可编辑的进度草稿。
- 示例稳定生成 AI 和雅思两条草稿，且数量单位不被误判为时长。
- 队列中每条草稿可以独立保存或放弃，其他草稿不受影响。
- 保存继续使用现有进度结构与校验，确认前不写入数据。
- Mock Provider 与未来真实 Provider 使用同一个多草稿接口。
- 单主题 AI、手动进度、历史补录、归档保护和批量计划无回归。
- 自动测试、人工验收、安全扫描、窄屏和 Git 范围检查均有可复现证据。
