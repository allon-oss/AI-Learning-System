# V1.3 第一阶段：AI 辅助生成学习进度草稿

**状态：开发完成，自动测试通过，待用户本地验收**

**确认日期：2026-08-25**

## 1. 背景与目标

当前系统已经支持手动新增学习进度，但用户每天学习后需要回忆并分别填写日期、主题、资料、计划、实际时长、完成度和简短总结。记录步骤较多，容易因为拖延或忘记而漏记。

V1.3 第一阶段的目标是降低一次学习结束后的记录成本：用户只需输入一段自由描述，系统通过独立的 AI 服务调用层生成一条可编辑的学习进度草稿，用户检查并确认后再保存。

本阶段不接入真实 AI API。系统使用可预测、可测试的 Mock Provider 模拟 AI 解析，同时保留未来接入 OpenAIProvider、DeepSeekProvider 等真实实现的接口边界。

## 2. 核心使用流程

1. 用户进入“学习进度”页面，在“AI 辅助记录”区域输入一段自由描述。
2. 用户点击“生成进度草稿”。
3. 页面把描述、参考日期和当前可用的方向、主题、资料、计划传给统一 AI 服务接口。
4. 当前 Mock Provider 使用规则解析描述，并尝试匹配系统已有数据。
5. 返回的草稿填入现有学习进度表单，页面显示缺失字段和匹配提示。
6. 用户检查并修改日期、主题、资料、计划、实际时长、完成度和简短总结。
7. 必填字段通过现有校验后，用户点击“确认并保存”。
8. 系统沿用现有进度保存逻辑，把记录写入 Local Storage。
9. 保存成功后清空自由描述和草稿状态。

用户也可以放弃草稿或继续使用原有的手动新增进度流程。未经用户确认，系统不得新增任何进度记录。

## 3. 草稿字段与保存规则

草稿沿用现有学习进度记录字段：

- `date`：记录日期。
- `topicId`：已有学习主题 ID。
- `resourceId`：已有学习资料 ID，可为空。
- `planId`：已有学习计划 ID，可为空。
- `durationMinutes`：实际学习时长，单位为分钟。
- `completionPercent`：本次完成度，范围为 0–100。
- `reflection`：简短总结，可为空，最多 500 字。

本阶段不新增 `learningContent` 字段。AI 识别出的学习内容用于匹配已有主题、资料和计划，并整理到现有 `reflection` 字段中。未来如果需要知识库或 RAG，再单独设计知识内容结构。

保存前继续遵守现有必填规则：

- 日期、学习主题、实际时长和完成度必须有效。
- 关联资料、学习计划和简短总结可以为空。
- 日期只能是今天或过去的有效日期。
- 完成度必须是 0–100 之间的整数。
- 实际时长必须是正整数分钟。

## 4. 已有数据匹配规则

### 4.1 总体约束

- AI 只能关联当前系统中已有的学习方向、活动主题、资料和计划。
- AI 不允许创建、修改、归档或删除任何方向、主题、资料或计划。
- Provider 只能返回已有数据的 ID，不能返回待自动创建的新对象。
- 无法唯一匹配时对应字段保持为空，并提示用户补充、手动选择或先创建对应主题。
- 传给 AI 服务层的上下文数据只能读取，不得原地修改。

### 4.2 日期

- 识别明确的 `YYYY-MM-DD` 日期以及“今天”“昨天”。
- 描述未包含日期时默认使用调用时传入的当天日期。
- 未来日期或无效日期不得静默改成今天，应将日期留空并给出提示。

### 4.3 学习主题与方向

- 只匹配未归档的已有主题。
- 学习方向用于缩小主题匹配范围和消除同名主题歧义，但不写入进度记录。
- 优先匹配描述中完整出现且名称最长的主题。
- 如果多个候选仍无法唯一确定，`topicId` 保持为空。
- 如果描述提到系统中不存在的主题，提示用户先创建主题，不自动新增。

### 4.4 学习资料

- 只匹配已有资料。
- 主题已确定时，只在该主题关联的资料中匹配。
- 无法唯一匹配时，`resourceId` 保持为空。

### 4.5 学习计划

- 只匹配已有计划。
- 计划必须符合现有进度关联规则：与进度属于同一主题，且计划日期不晚于进度日期。
- 无法唯一匹配时，`planId` 保持为空。

### 4.6 实际时长

- 识别“45 分钟”“1 小时”“1.5 小时”等带明确数值和单位的描述。
- 小时统一换算成分钟，小数小时按分钟换算后得到正整数。
- 没有明确数值或解析结果无效时，`durationMinutes` 保持为空。

### 4.7 完成度

- 识别 `0%` 到 `100%` 之间的明确百分比。
- 没有明确数字时不推测完成度，`completionPercent` 保持为空。

### 4.8 简短总结

- 使用整理后的原始学习描述作为简短总结，保留实际学习内容。
- 最终结果不得超过现有 500 字限制。
- 原始自由描述不单独持久化。

## 5. 模块边界与统一接口

### 5.1 `AIService`

新增独立的 `src/ai-service.js`，作为页面调用 AI 能力的唯一入口：

- 公开稳定的异步草稿生成方法。
- 委托当前 Provider 生成结果。
- 统一校验和标准化 Provider 的返回结构。
- 统一处理 Provider 异常或格式错误。
- 不读取或写入 Local Storage。
- 不操作页面 DOM。
- 不直接保存学习进度。

### 5.2 `MockAIProvider`

新增独立的 `src/mock-ai-provider.js`：

- 实现与未来真实 Provider 相同的调用接口。
- 使用本需求定义的确定性规则解析自由描述。
- 返回学习进度草稿、缺失字段和提示。
- 核心解析逻辑保持纯函数特征，便于在 Node 测试中独立验证。

### 5.3 统一调用接口

```text
generateProgressDraft({
  description,
  referenceDate,
  context: {
    directions,
    topics,
    resources,
    plans
  }
})
```

统一返回结构：

```text
{
  draft: {
    date,
    topicId,
    resourceId,
    planId,
    durationMinutes,
    completionPercent,
    reflection
  },
  missingFields,
  warnings
}
```

`missingFields` 用于标识未识别或无效的字段，`warnings` 用于向用户解释匹配失败、歧义或关联限制。页面不得依赖 Mock 的内部解析函数。

返回结构必须始终包含全部 `draft` 键。无法识别的字段使用 `null`，没有总结时 `reflection` 使用空字符串；`missingFields` 使用上述字段名，`warnings` 使用可直接展示给用户的文本数组。这样未来 Provider 的实现可以替换，但页面不需要猜测缺失字段的表达方式。

### 5.4 未来 Provider

未来的 `OpenAIProvider`、`DeepSeekProvider` 或其他 Provider 必须实现相同输入输出约定。替换 Provider 时不应重写页面草稿确认和进度保存流程。

本阶段不实现：

- Provider 选择界面。
- 真实网络请求。
- API Key 配置或保存。
- 模型名称配置。
- 服务器或云端部署。

## 6. 页面与交互设计

- 在现有“学习进度”表单上方新增“AI 辅助记录”区域。
- 区域包含自由描述输入框、“生成进度草稿”按钮、状态信息和“放弃草稿”操作。
- 描述为空时不调用服务，提示用户先输入学习描述。
- 生成期间禁用生成按钮并显示处理中状态，避免重复调用。
- 草稿生成成功后才覆盖进度表单字段。
- 页面进入明确的“草稿待确认”状态，显示已识别结果、必填缺失项和可选缺失项。
- 草稿中的全部字段都允许用户手动修改。
- 草稿状态下，现有保存按钮显示为“确认并保存”。
- 用户再次生成时，使用当前描述覆盖尚未保存的草稿。
- 用户放弃草稿时清除 AI 描述、提示和草稿状态，不删除任何已有记录。
- AI 辅助只用于新增进度，不用于编辑已有进度。
- 手动新增和编辑已有进度的流程继续保持可用。

## 7. 错误处理与安全边界

- Provider 抛出异常时保留原始描述，不保存数据，也不覆盖用户当前已填写的进度表单。
- Provider 返回格式错误时，由 `AIService` 拦截并显示“草稿生成失败，请重试或手动填写”。
- 草稿缺少日期、主题、实际时长或完成度时阻止保存，并指出需要补充的字段。
- 资料、计划或总结缺失时只显示提示，不阻止保存。
- 草稿生成、放弃或失败都不得修改现有主题、资料、计划、笔记或进度记录。
- 未经用户确认，不写入任何进度记录。
- 本阶段不存在 API Key、访问令牌或其他秘密配置，不向代码、Local Storage 或 Git 写入敏感信息。

## 8. 兼容性要求

- 保持现有学习进度数据结构不变，不执行 Local Storage 数据迁移。
- 确认保存必须复用现有进度校验和保存逻辑，不能建立第二套保存规则。
- 现有手动新增、编辑、删除、历史日期补录、归档主题保护和计划关联规则保持不变。
- 保存 100% 完成度仍不得自动修改计划完成状态或资料整体状态。
- V1.2 的自定义学习方向只作为匹配上下文使用，不改变方向管理规则。
- 页面在 390px 宽度下不得出现横向溢出。

## 9. 不包含内容

- 不接入 OpenAI、DeepSeek 或其他真实 AI API。
- 不配置、读取或保存 API Key。
- 不新增服务器、账户系统或云部署。
- 不从 Notion、聊天、语音、浏览器历史或其他外部来源自动收集数据。
- 不自动创建主题、资料、计划或笔记。
- 不自动生成学习笔记。
- 不自动保存 AI 草稿。
- 不自动修改计划完成状态或资料状态。
- 不新增 `learningContent`、知识库或 RAG 数据结构。
- 不实现多轮 AI 对话、提醒或定时任务。

## 11. 人工验收场景

测试前使用独立浏览器资料目录或专用测试数据，避免覆盖日常学习记录。先创建可供匹配的主题、资料和计划，再输入：

```text
今天学习 Transformer 入门 45 分钟，
使用注意力机制视频，
完成今天的“看完第二章”计划 70%，
还需要继续理解多头注意力。
```

系统应生成接近下列内容的草稿：

```text
日期：今天
主题：匹配已有 Transformer 入门
资料：匹配已有注意力机制视频
计划：匹配已有“看完第二章”
实际时长：45 分钟
完成度：70%
简短总结：保留并整理本次学习内容
```

人工确认：

1. 生成草稿前 Local Storage 中没有新增进度。
2. 草稿中的每个字段均可手动修改。
3. 点击“确认并保存”后只新增一条符合现有结构的进度记录。
4. 刷新页面后记录仍存在，统计摘要正确更新。
5. 对不存在或有歧义的数据不自动创建或错误关联。
6. 放弃草稿、生成失败或必填字段不完整时不新增记录。
