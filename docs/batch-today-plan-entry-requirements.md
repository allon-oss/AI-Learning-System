# 批量录入多主题今日计划需求

## 1. 背景

当前新增计划一次只能保存一条记录。用户一天同时安排 AI、雅思等多个主题时，需要反复选择主题、填写任务并保存，重复操作较多。

本阶段增加“批量录入今日计划”入口，让用户一次组织多个主题及其任务，统一校验后保存。批量能力只优化录入过程，不改变主题、计划、资料、进度之间的既有关系。

## 2. 目标

- 一次录入多个活动主题的今日计划。
- 同一主题只选择一次，可以在主题组内添加多条任务。
- 每条任务保存为独立计划，并保留自己的资料、预计时长和优先级。
- 资料、预计时长和优先级默认折叠，只显示“主题 + 任务名称”。
- 统一保存必须全量校验；任何一条无效时不得部分保存。
- 单条计划、未来计划、历史补录、计划完成和学习进度关联规则保持不变。

## 3. 名词

- **单条录入**：现有计划表单，一次创建一条计划，继续支持普通计划和历史补录。
- **批量今日计划**：本阶段新增的临时表单，只创建当天的普通计划。
- **主题组**：一次选择一个活动主题，组内包含一条或多条计划任务。
- **任务行**：最终会保存为一条独立计划的草稿行。
- **更多设置**：任务行内默认折叠的资料、预计时长和优先级字段。

## 4. 典型场景

用户在批量模式填写：

- AI 学习
  - 测试学习系统
  - 学 RAG
- 雅思
  - 背单词
  - 做阅读

统一保存后，系统生成四条计划。AI 两条计划的 `topicId` 指向 AI 主题，雅思两条计划的 `topicId` 指向雅思主题。

## 5. 范围

### 5.1 包含

- 在计划区域切换“单条录入”和“批量录入今日计划”。
- 新增、删除主题组。
- 在一个主题组内新增、删除任务行。
- 每个主题组只能选择一个活动主题，同一主题不能在两个组中重复出现。
- 每条任务行包含：
  - 任务名称，必填；
  - 关联资料，可选；
  - 预计时长，可选；
  - 优先级，必填并默认“中”。
- 更多设置默认折叠；展开状态只属于当前页面，不持久化。
- 保存成功后显示保存数量，并切换计划列表到“今天”。
- 页面跨过本地午夜后更新批量日期；提交时以提交瞬间的本地日期为准。

### 5.2 不包含

- 批量创建未来计划。
- 批量创建历史补录计划。
- 自然语言解析或 AI 自动生成批量计划。
- 批量计划的批次 ID、批次记录或新的 Local Storage 键。
- 批量编辑、整批删除、整批撤销。
- 自动去重、自动合并相同任务。
- 复制到明天、自动顺延或计划状态扩展。
- 批量草稿自动保存；刷新页面前未保存的草稿可以丢失。

## 6. 界面与交互

### 6.1 模式切换

- 计划表单区域提供“单条录入”和“批量今日计划”两个入口。
- 默认显示现有单条录入。
- 切换模式不得修改已保存数据。
- 同一页面会话内，从批量切回单条再切回来时，尚未保存的批量草稿应保留。
- 保存成功后重置批量草稿为一个主题组和一条空任务，但保留在批量模式。

### 6.2 批量日期

- 批量表单明确显示“计划日期：今天的本地日期”。
- 日期不可在批量表单中编辑。
- 跨过本地午夜、页面重新可见或用户再次聚焦批量表单时刷新日期。
- 若用户希望录入未来或过去日期，页面引导其使用单条录入。

### 6.3 主题组

- 初始显示一个主题组和一条任务行。
- 主题下拉框只显示未归档主题。
- 已被其他主题组选中的主题在其他组中不可再次选择。
- 仍存在未选择主题时，可以点击“添加主题”。
- 全部活动主题都已使用时，“添加主题”不可用并说明原因。
- 至少保留一个主题组；最后一个主题组不能删除，只能清空或更换主题。
- 主题在表单打开期间被归档或删除时，提交必须阻止全部保存并指出对应主题组。

### 6.4 任务行

- 每个主题组初始至少有一条任务行。
- 可以点击“添加同主题任务”增加任务行。
- 每条可删除；一个主题组至少保留一条任务行。
- 任务名称始终可见。
- “更多设置”按钮使用 `aria-expanded` 表达展开状态，并与对应详情区域建立关联。
- 折叠不会清空已经填写的资料、预计时长或优先级。
- 详情字段发生错误时，系统自动展开该行并显示错误。

### 6.5 资料选项

- 资料下拉框只显示当前主题关联的资料。
- 主题为空时资料不可选。
- 更换主题后，若原资料不属于新主题，必须清除原选择。
- 提交时再次检查资料是否仍存在并属于当前主题，不能只依赖下拉框过滤。

## 7. 数据结构

批量表单不保存自身结构。每条任务转换为现有计划对象：

```js
{
  id: "plan-<batch timestamp>-<row index>",
  date: "YYYY-MM-DD",
  topicId: "topic-id",
  resourceId: "resource-id" || null,
  task: "任务名称",
  priority: "高" | "中" | "低",
  estimatedMinutes: 45 || null,
  isCompleted: false,
  isBackfilled: false,
  createdAt: "ISO timestamp"
}
```

约束：

- `date` 是提交时的本地今天。
- `topicId` 是所属主题组的主题 ID。
- `resourceId` 必须为空，或属于同一 `topicId`。
- `task` 裁剪首尾空白后不能为空。
- `estimatedMinutes` 为空时保存 `null`，否则必须为正整数。
- `priority` 只允许“高”“中”“低”。
- `isCompleted` 始终为 `false`。
- `isBackfilled` 始终为 `false`。
- 同一批次内每条计划的 `id` 必须唯一。
- 不新增 `batchId`，不改变现有计划、进度或主题对象结构。

## 8. 校验与原子保存

保存前必须先收集全部主题组和任务行，再执行完整校验：

1. 至少有一个主题组。
2. 每个主题组选择一个活动主题。
3. 同一主题不能在多个主题组重复。
4. 每个主题组至少有一条任务。
5. 每条任务名称有效。
6. 资料仍存在且属于该主题。
7. 预计时长为空或为正整数。
8. 优先级合法。

只要存在任一错误：

- 不创建任何计划对象；
- 不修改内存中的 `plans`；
- 不写入 `personal-learning-system-plans`；
- 保留全部批量草稿；
- 展开包含隐藏字段错误的任务行；
- 聚焦第一处错误，并显示“尚未保存任何计划”。

全部有效时：

- 使用一个批次时间戳和稳定行序号生成唯一 ID；
- 按页面填写顺序创建计划；
- 使用一个 `createdAt` 时间值；
- 组成 `nextPlans = [...newPlans, ...plans]`；
- 一次写入现有计划 Local Storage 键；
- 写入成功后才替换内存中的 `plans` 并重置批量草稿；
- 显示“已保存 N 条今日计划”。

## 9. 顺序与独立操作

- 新计划在今天列表中的顺序与批量表单顺序一致：先按主题组顺序，再按组内任务顺序。
- 保存后每条计划仍可独立完成、取消完成和删除。
- 删除或完成其中一条不得影响同批其他计划。
- 主题详情和资料详情继续按每条计划的 `topicId`、`resourceId` 统计。

## 10. 兼容性与安全

- 现有单条计划表单和历史补录规则保持不变。
- 旧计划缺少 `isBackfilled` 时继续按现有兼容规则标准化。
- 批量表单只使用活动主题；归档主题的历史计划不被修改。
- 不新增依赖、后端、API、MCP、Connector 或权限。
- 不读写 Token、API Key、密码、`.env` 或其他敏感配置。
- 390px 宽度下不得出现横向溢出。
- 动态控件必须有可访问名称、错误关联和键盘可操作性。

## 11. 自动测试范围

### 11.1 数据模型

- 多主题、多任务草稿转换为稳定的有效条目。
- 任务名称裁剪；预计时长转换为整数或 `null`；优先级保持合法值。
- 空主题、归档主题、重复主题组、空任务、错误资料、错误时长和错误优先级返回明确错误。
- 任何错误存在时不返回可保存的部分条目。
- 校验不修改传入主题、资料或草稿数组。

### 11.2 页面

- 默认显示单条录入，进入批量模式后显示一个主题组和一条任务。
- 同主题增加任务、增加第二主题、删除任务和删除主题组正常。
- 更多设置默认折叠，展开后值可填写；折叠再展开不丢失。
- 资料按主题过滤，更换主题后不合法资料被清除。
- AI 两条、雅思两条统一保存后生成四条独立计划。
- 四条计划的 `topicId`、`resourceId`、`estimatedMinutes`、`priority`、`date` 和标记正确。
- 四条计划 ID 唯一，显示顺序与输入顺序一致。
- 任一行无效时计划存储完全不变，草稿保留并聚焦错误。
- 活动主题在提交前被归档时整批保存被拒绝。
- 保存 4 条后刷新页面，四条记录和关联保持不变。
- 其中一条完成或删除不影响其他三条。
- 跨午夜后批量日期更新，并按新的今天保存。
- 单条今天、未来和历史补录回归通过。
- 390px 宽度下无横向溢出、无页面错误。

## 12. 人工验收场景

1. 批量模式默认只显示主题和任务名称，更多设置折叠。
2. AI 主题添加“测试学习系统”“学 RAG”，雅思主题添加“背单词”“做阅读”。
3. 为不同任务填写不同资料、预计时长和优先级；折叠再展开确认值保留。
4. 统一保存后今天列表显示四条计划，顺序和关联正确。
5. 刷新页面后四条计划仍存在，各自可独立完成、取消完成和删除。
6. 制造一个空任务或错误时长，确认整批不保存，已填写内容不丢失。
7. 更换主题，确认不属于新主题的资料被清除。
8. 归档已选主题后尝试保存，确认整批拒绝且历史数据不变。
9. 单条录入的今天、未来和历史补录仍正常。
10. 390px 宽度下完成新增主题组、任务、展开详情和保存，无横向滚动及 JavaScript 错误。

## 13. 阶段边界

- 本文档只定义批量今日计划录入。
- 开发必须建立在历史补录日期规则已经人工验收、更新状态文档并完成 Git 保存的基线上。
- 当前实现已进入人工验收门禁；在用户完成并接受人工验收前，不更新 `project-status.md`，不暂存或提交 Git，不合并或推送，也不开始下一个功能。
