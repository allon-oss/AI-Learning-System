# V1.3 AI 辅助学习进度草稿人工验收

状态：待用户本地执行（自动测试通过不代表人工验收完成）

## 使用前准备

1. 使用独立浏览器资料目录或专用 Local Storage，避免改动日常数据。
2. 在系统中准备一个未归档主题“Transformer 入门”、同主题资料“注意力机制视频”和当天计划“看完第二章”。打开浏览器开发者工具的 Application/Storage 面板，观察 `personal-learning-system-progress-records`。
3. 每个场景开始前记录进度数组长度；除明确保存的场景外，预期长度不变。不要把真实 API Key、Token 或真实端点写入任何输入、代码或 Local Storage。

## 验收步骤

### 1. 完整匹配、确认前不保存、修改后保存

输入：`今天学习 Transformer 入门 45 分钟，使用注意力机制视频，完成今天的看完第二章计划 70%，还需要继续理解多头注意力。`

点击“生成进度草稿”。预期：日期为今天，主题/资料/计划匹配，时长为 45，完成度为 70%，总结可编辑；按钮进入“确认并保存”。此时 Local Storage 进度数组长度和原内容不变。

把完成度改为 `75`，点击“确认并保存”。预期：只新增一条记录，保存值为 75；刷新后仍存在；自由描述和草稿状态清空。

### 2. 不存在或有歧义的主题

分别输入不存在主题（如“学习不存在的量子课程”）和两个同名主题无法区分的描述并生成。预期：不创建新主题、不错误关联，主题为空并提示手动选择/先创建；未确认前进度数组不变。补齐合法必填字段后可正常保存一条记录。

### 3. 缺失必填项、未来日期和可选字段为空

测试缺少时长、缺少完成度、未来日期（如 `2099-01-01`）的描述。预期：对应字段为空并提示，确认保存被阻止，Local Storage 不变。资料、计划或总结为空只提示、不阻止保存；补齐日期、主题、正整数时长和 0–100 整数完成度后才可保存。

### 4. 失败、放弃和重复生成

让 Provider 失败后点击生成。预期：显示失败提示，原描述和原手动表单值保留，Local Storage 不变。

成功生成后点击“放弃草稿”。预期：描述、提示、草稿字段清空，按钮恢复“保存进度”，不新增记录。

在生成处理中快速连续点击生成。预期：按钮暂时禁用，Provider 只处理一次；最终只显示一次结果，无重复保存。

### 5. 编辑隔离与手动新增

先用普通表单手动新增一条进度并刷新，再编辑已有进度。预期：编辑时 AI 区域隐藏或不可用于覆盖编辑；保存后仍只有原记录数量，原字段结构不增加。退出编辑后手动新增流程仍可用。

### 6. 完成度 100%、归档保护

生成或手动保存完成度 `100` 的记录。预期：计划完成状态和资料整体状态不被自动修改。

归档一个主题后尝试生成或手动选择该主题。预期：归档主题不会出现在新建选择项；历史记录的归档关联保留且受保护，不被草稿流程改写。

### 7. 安全范围、窄屏和控制台

在源码和浏览器存储中确认不存在 `learningContent`、API Key、Token、真实 API 端点或 Provider 配置；AI 流程只使用 Mock Provider 和统一 AI Service。将视口设为 390×844，执行完整匹配场景。预期：页面无横向滚动溢出；控制台无 JavaScript 错误。

## 记录结果

逐项记录“通过/失败/未执行”、浏览器与日期；失败时附现象和不含敏感信息的截图或控制台错误。未实际操作的项目必须保持“待执行”，不得用自动测试结果替代人工验收。
