## 验收前准备

1. 启动并打开当前批量计划功能 worktree 页面（使用本次功能对应的页面，不要打开旧页面）。
2. 在主题管理中准备两个处于启用状态的主题：一个 AI 主题、一个 IELTS 主题，例如“AI 学习”和“IELTS 学习”。
3. 为每个主题至少准备一个主题专属资源，并确认资源分别属于正确主题。资源名称可用“验收-AI 资源”和“验收-IELTS 资源”。
4. 记录测试开始前页面显示的今日计划数量；后续每个“新增计划”结果都以这个基线数量核对。
5. 本次测试创建的主题、资源和计划记录请使用安全名称，计划任务统一使用 `验收-` 前缀，例如 `验收-测试学习系统`。不要把真实账号、密钥或个人敏感信息写入名称、描述或资源内容。
6. 如需清理测试数据：在计划列表中使用每条计划自己的“删除”操作；在主题/资源管理中删除本次创建的“验收-”主题或资源。删除前确认名称，避免误删原有数据；若页面没有删除主题/资源入口，请保留记录并向项目维护者报告，不要直接改文件或浏览器存储。
7. 准备浏览器开发者工具的 Console（控制台），在出现错误时查看是否有 JavaScript 错误；测试结束前再次检查控制台。

1. 打开计划录入页面并切换到批量模式。
2. 不点击“更多设置”，观察每个批量任务行最初显示的字段。

预期结果：

- 每行初始只显示主题和任务字段。
- “更多设置”区域默认收起，资源、分钟数、优先级等高级字段不占据展开状态。

结果：通过

4. 在同一 IELTS 主题下再添加任务 `验收-做阅读`。
5. 确认四行均仍在页面上，并检查每一行的主题和任务文字。

预期结果：

- 页面显示四个待保存任务，文字与输入完全一致。
- 前两项关联 AI 主题，后两项关联 IELTS 主题；添加一行不会覆盖其他行。

结果：通过

## 场景 3：高级设置保留不同值

操作：

1. 对四个任务分别展开“更多设置”。
2. 为每行选择对应主题的资源，并填写互不相同的分钟数，例如 15、25、35、45。
3. 为四行选择不同的优先级（按页面可选值分配）。
4. 收起所有“更多设置”，再逐行重新展开。

预期结果：

- 每个任务都只能选择其主题的资源。
- 每行的资源、分钟数和优先级都保留各自的值，没有串到另一行。
- 收起再打开不会清空或重置草稿。

结果：通过

## 场景 4：统一保存生成四条今日计划

操作：

1. 在四行都填写有效内容后，按页面顺序点击一次统一保存/提交按钮。
2. 回到今日计划列表，记录新计划并与保存前的基线数量比较。
3. 按页面原顺序核对四条计划的任务、主题、资源、分钟数和优先级。

预期结果：

- 一次提交恰好新增四条今日计划，不多不少。
- 列表中的顺序与批量表单的四行顺序一致。
- 每条计划都关联正确主题和资源，属性值与各自行的输入一致。

结果：通过

## 场景 5：刷新后仍可独立处理

操作：

1. 刷新页面或关闭后重新打开页面。
2. 确认场景 4 的四条计划仍存在。
3. 先点击第二条计划的“完成”，确认只有第二条变为已完成；再点击同一条计划的“取消完成”，确认只有第二条恢复为未完成。
4. 再将第一条设为完成、删除第三条、让第四条保持不变（如页面要求确认，按确认操作）。
5. 刷新页面，再查看四条计划的结果。

预期结果：

- 刷新后保存的计划仍在，状态持久化。
- 第二条完成再取消完成时，只有第二条的状态来回切换，其他三条始终不变。
- 完成、取消完成、删除互不影响：一条的操作不会改变其他计划的任务、主题或状态。
- 删除只移除选中的第三条；第一条保持完成，第二条恢复未完成，第四条保持原状态。

结果：通过

## 场景 6：空任务与无效时长不产生计划

操作：

1. 第 A 轮：在同一批量草稿中建立至少两行；一行填写完整有效任务作为兄弟行，另一行选择主题但把任务名称留空，其他值保持有效，然后统一提交。
2. 第 A 轮提交后观察错误提示、焦点和草稿；确认今日计划零新增，且有效兄弟行与空任务行的全部草稿仍保留。修正或清理本轮草稿后再开始下一轮。
3. 第 B 轮：重新建立同样结构的批量草稿，仍保留至少一行完整有效兄弟任务；另一行填写有效任务名称，但输入无效时长（例如 0、负数、非数字或未完成的数字），然后统一提交。
4. 第 B 轮提交后观察错误提示、焦点和展开的分钟详情；确认今日计划零新增，且有效兄弟行与无效分钟行的全部草稿仍保留。
5. 回到今日计划列表，分别将两轮提交后的数量与各轮提交前基线比较。

预期结果：

- 两轮使用的同批有效兄弟行都不能被部分保存；空任务轮和无效时长轮各自新增计划数量均为 0。
- 页面显示清楚的校验消息，焦点落在需要修正的字段（若浏览器支持自动聚焦）。
- 每轮的有效兄弟行和无效行都完整保留，用户可以直接修正，而不是只保留一部分或整批被静默清空。
- 错误详情/明细可见，且控制台没有未处理的页面异常。

结果：通过

- 页面说明主题已归档，并保留可诊断的输入/错误详情。
