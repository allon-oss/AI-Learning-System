# V1.3.1 普通计划与历史补录人工验收

**状态：用户本地人工验收通过（2026-08-31）**

**范围：验证普通计划与历史补录的日期边界、事后补录标记、历史进度关联和原计划日期保护。**

## 测试前准备

1. 启动当前功能分支页面，准备两个未归档主题：一个属于 AI 学习，一个属于雅思英语学习。
2. 建议测试主题分别命名为“验收-AI”和“验收-雅思”；记下测试前计划与进度数量。
3. 使用昨天、今天和明天三个日期完成以下场景。不要填写密码、Token、API Key 或其他敏感信息。
4. 测试记录可以在验收结束后通过页面删除。

## 场景 1：普通计划拒绝过去日期

1. 在“记录方式”保持“普通计划（今天或未来）”。
2. 在“学习任务”填写“验收-普通计划过去日期不应保存”，手动输入昨天。
3. 预期立即提示普通计划只能选择今天或未来，并引导选择“历史补录”。
4. 预期“添加计划”按钮不可用；刷新后计划数量没有增加。

结果：通过

## 场景 2：普通计划仍支持今天和未来

1. 普通模式分别新增“验收-今天计划”和“验收-未来计划”。
2. 日期分别选择今天和明天，预期都能保存。
3. 预期今天计划出现在“今天”，明天计划出现在“未来”。
4. 刷新页面，确认日期和所属主题保持不变，两条计划都没有“事后补录”标记。

结果：通过

## 场景 3：历史补录只允许过去日期

1. 将“记录方式”切换为“历史补录（事后记录）”。
2. 预期日期自动变为昨天，日历不能选择今天或未来。
3. 手动输入今天，预期立即提示历史补录只能选择过去日期，按钮不可用。
4. 改回昨天，预期提示消失，按钮恢复可用。
5. 切回普通计划，预期无效的过去日期自动恢复为今天。

结果：通过

## 场景 4：补录计划进入历史并保留独立完成状态

1. 选择“验收-AI”主题、历史补录和昨天，任务填写“验收-昨天学 Codex”。
2. 保存后预期自动切换到“历史”视图。
3. 预期卡片日期仍为昨天，显示“事后补录”，状态为“未完成”，不显示“已逾期”。
4. 刷新页面，确认日期、标记和未完成状态保持不变。
5. 点击“完成”再“取消完成”，确认这是显式操作；系统没有因补录而自动完成计划。

结果：通过

## 场景 5：补录昨天进度并关联补录计划

1. 在“新增进度记录”选择昨天和“验收-AI”主题。
2. 在关联计划中选择“验收-昨天学 Codex”，填写实际时长 40 分钟、完成度 100% 和一段总结。
3. 保存后预期进度日期仍为昨天，并显示关联计划。
4. 回到历史计划，确认计划日期仍是昨天，没有被改成今天。
5. 确认计划完成状态没有因 100% 进度自动改变。

结果：通过

## 场景 6：未来日期不能补录进度

1. 在进度表单手动输入明天，填写其他必填项并尝试保存。
2. 预期浏览器或页面拒绝保存；刷新后进度数量没有增加。
3. 预期此前的补录计划日期和完成状态没有变化。

结果：通过

## 场景 7：AI 与雅思两组补录关联不串联

1. 再新增一条昨天的历史补录计划：选择“验收-雅思”，任务填写“验收-昨天背单词”。
2. 为它新增昨天的进度，例如 20 分钟、完成度 80%，并明确选择雅思补录计划。
3. 查看两条历史计划：Codex 计划只统计 AI 进度，背单词计划只统计雅思进度。
4. 编辑或查看两条进度，确认各自的主题和关联计划没有互换。
5. 本阶段仍是逐条保存；不应出现批量录入或 AI 自动拆分入口。

结果：通过

3. 新增、补录和刷新过程中，旧计划日期及关联信息不发生变化。

结果：通过
